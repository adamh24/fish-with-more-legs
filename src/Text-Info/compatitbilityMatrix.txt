**ingredient-level signals**

For each pair of flavours i, j, compute:

C(i, j) = 100 x clamp(W_p ⋅ S_profile + W_c ⋅ S_category + W_s ⋅ S_strength + W_a ⋅ S_acid, 0,1)  

C(i, j) = compatibility between flavour i and j (as a %)

Signals
W_p = weight of profile 
W_c = weight of category
W_s = weight of strength
W_a = weight of acid

S_profile = similarity score between flavour profiles
S_category = similarity score between categories
S_strength = intesity compatibility score
S_acid = acid compatibility score 


**3. render compatibility score**
Render percentage along with visual


If you have N flavours:
- Create an NxN matrix
- Diagonal is 100 (self-compatibility)
- Enforce symmetry: $C_{ij} = C_{ji}$ by averaging both directions if needed
- Save as:
`{ flavourId: { otherFlavourId: score } }` or a 2D array for faster lookup

**4. Normalize and bucket for UX**
Convert score to labels:
- 80-100: Excellent
- 60-79: Good
- 40-59: Experimental
- 0-39: Low

This gives you both a number and human-readable guidance.

**5. Render as a heatmap + pair explorer**
- Rows/columns = flavour names
- Cell color = compatibility score
- Click a cell to show “why” breakdown (profile, category, recipe evidence)
- Add sorting/filtering by profile or category

**6. Improve over time with feedback**
When users like/dislike pairings:
- Store feedback as +1/-1
- Update scores incrementally:
$C'_{ij} = (1-\alpha)C_{ij} + \alpha F_{ij}$
with small $\alpha$ (e.g. 0.1)

This turns it from static rules into a learning system.
